# 博客文章管理功能开发计划

**目标**：实现基于 Markdown 文件上传的博客文章管理后台，支持新增、更新、列表查看、下载、删除。

**技术栈**：后端 Rust/Salvo + SeaORM，前端 React 18 + TypeScript + Vite

---

## 阶段一：后端 — Admin 鉴权中间件

**目标**：所有管理接口统一校验博主身份，非博主返回 403。

### 涉及文件
- `src/config/mod.rs` — 读取 `ADMIN_GITHUB_ID` 环境变量
- `src/middleware/admin_auth.rs` — 新增中间件文件
- `src/routes/mod.rs` — 注册 admin 路由组

### 任务清单

- [ ] 在 `application.yaml` 或环境变量中新增 `ADMIN_GITHUB_ID` 配置项
- [ ] 在 `src/config/mod.rs` 中读取并暴露该配置
- [ ] 新建 `src/middleware/admin_auth.rs`，逻辑如下：
  - 从请求头提取 `Authorization: Bearer <token>`
  - 验证 JWT 合法性（复用现有 `config/auth.rs` 的验证逻辑）
  - 取出 `sub`（GitHub user ID）与配置的 `ADMIN_GITHUB_ID` 比对
  - 不一致则直接返回 `403 Forbidden`
- [ ] 在 `src/routes/mod.rs` 中新增 `/api/admin` 路由组，挂载该中间件

### 验收标准
- 用博主 GitHub 账号登录后请求 `/api/admin/ping` 返回 200
- 用其他账号 token 请求返回 403
- 无 token 请求返回 403

## 阶段二：后端 — 文章上传接口（新增 / 更新）

**目标**：接收 `.md` 文件，解析 frontmatter，自动判断新增或更新。

### 涉及文件
- `src/handler/admin/article.rs` — 新增处理器
- `src/routes/admin.rs` — 新增路由
- `src/vo/request/admin_article.rs` — 请求 VO
- `Cargo.toml` — 新增 `gray_matter` 或 `yaml-front-matter` 依赖用于解析 frontmatter

### Frontmatter 字段约定

```yaml
---
article_id: "abc-123"          # 可选，有则更新，无则新增
title: "文章标题"
summary: "一句话摘要"
category: "技术"
tags: ["Rust", "后端"]
status: "draft"                # draft | published
weight: 0
published_time: "2026-07-14T10:00:00"  # 可选，新增时默认当前时间
---
```

### 任务清单

- [ ] `Cargo.toml` 添加 frontmatter 解析依赖（推荐 `gray_matter`）
- [ ] 新建 `src/handler/admin/article.rs`，实现 `upload_article` 处理器：
  - 接收 `multipart/form-data`，提取 `.md` 文件内容
  - 解析 frontmatter，提取元数据字段
  - 校验必填字段（`title` 不能为空）
  - 判断逻辑：
    - `article_id` 存在 → 查库确认存在 → `UPDATE`
    - `article_id` 不存在 → 生成 UUID → `INSERT`
  - 返回结构：`{ article_id, title, is_new: bool }`
- [ ] 在 `src/routes/admin.rs` 注册：`POST /api/admin/articles/upload`
- [ ] 挂载 admin 路由组到主路由（带阶段一中间件）

### 验收标准
- 上传无 `article_id` 的 MD → 数据库新增记录，返回新生成的 `article_id`
- 上传有 `article_id` 的 MD → 对应记录被更新，`content_md`/`title` 等字段正确变更
- 上传格式错误的文件 → 返回 400 及错误描述

## 阶段三：后端 — 文章管理接口（列表 / 删除 / 下载）

**目标**：提供后台管理所需的其余三个接口。

### 涉及文件
- `src/handler/admin/article.rs` — 追加三个处理器
- `src/routes/admin.rs` — 追加三条路由
- `src/vo/response/admin_article.rs` — 管理侧响应 VO

### 任务清单

**3.1 文章列表（含草稿）**
- [ ] 实现 `list_articles` 处理器：
  - 支持分页参数 `page_no` / `page_size`
  - 支持 `status` 过滤（`all` / `draft` / `published`）
  - 返回字段：`article_id, title, summary, status, category, tags, published_time, update_time`
  - **注意**：与公开接口的区别是不过滤 `draft` 状态
- [ ] 注册：`GET /api/admin/articles`

**3.2 删除文章**
- [ ] 实现 `delete_article` 处理器：
  - 路径参数 `:article_id`
  - 硬删除，不可恢复
  - 文章不存在返回 404
- [ ] 注册：`DELETE /api/admin/articles/:article_id`

**3.3 下载原始 MD**
- [ ] 实现 `download_article_md` 处理器：
  - 查出 `content_md` 及所有元数据字段
  - 拼装完整 frontmatter + 正文内容
  - 设置响应头 `Content-Disposition: attachment; filename="{title}.md"`
  - 返回纯文本 MD 内容
- [ ] 注册：`GET /api/admin/articles/:article_id/download`

### 验收标准
- 列表接口返回含草稿的全部文章，分页正常
- 删除后文章从数据库移除，再次查询返回 404
- 下载接口返回合法的 MD 文件，frontmatter 字段与数据库一致

## 阶段五：前端 — 文章上传功能

**目标**：提供 MD 文件上传入口，上传后展示结果（新文章显示 article_id 供复制）。

### 涉及文件
- `src/pages/admin/components/upload-panel/index.tsx` — 上传面板组件
- `src/api/endpoint/admin.ts` — 追加 upload 接口

### 任务清单

- [ ] 实现上传面板组件，功能点：
  - 拖拽上传区域（`dragover` / `drop` 事件）
  - 点击选择文件按钮（`accept=".md"`）
  - 文件选中后显示文件名预览
  - 「确认上传」按钮触发请求
  - 上传中显示 loading 状态，禁止重复提交
- [ ] 上传成功后的结果展示：
  - **新文章**：绿色提示框显示 `article_id`，右侧一键复制按钮（复用 toast 提示"已复制"）
  - **更新文章**：提示"《标题》已更新"
- [ ] 上传失败展示错误信息（来自后端 `msg` 字段）
- [ ] 在 `src/api/endpoint/admin.ts` 添加：
  ```typescript
  uploadArticle(file: File): Promise<{ article_id: string, title: string, is_new: boolean }>
  ```
  请求头需携带 JWT token（复用现有 axios 拦截器）

### 验收标准
- 拖拽和点击两种方式均可选择文件
- 上传无 `article_id` 的 MD → 页面显示生成的 `article_id`，点击可复制
- 上传有 `article_id` 的 MD → 页面显示更新成功提示
- 上传非 `.md` 文件 → 前端直接拦截提示格式错误

## 阶段六：前端 — 文章列表管理

**目标**：展示所有文章（含草稿），支持下载原始 MD 和删除操作。

### 涉及文件
- `src/pages/admin/components/article-list/index.tsx` — 列表组件
- `src/api/endpoint/admin.ts` — 追加列表、删除、下载接口

### 任务清单

- [ ] 实现文章列表组件：
  - 顶部状态筛选 Tab：全部 / 已发布 / 草稿
  - 列表字段：标题、状态标签（草稿/已发布）、分类、标签、更新时间
  - 操作列：「下载 MD」「删除」
- [ ] 「下载 MD」：
  - 调用下载接口，触发浏览器文件下载
  - 文件名格式：`{title}.md`
- [ ] 「删除」：
  - 点击先弹出确认提示（"确认删除《标题》？此操作不可恢复"）
  - 确认后调用删除接口，成功后刷新列表
- [ ] 分页：每页 10 条，底部分页控件
- [ ] 在 `src/api/endpoint/admin.ts` 追加三个接口定义

### 验收标准
- 列表正确展示草稿和已发布文章
- Tab 切换后列表正确过滤
- 下载的 MD 文件 frontmatter 字段与数据库一致
- 删除后列表自动刷新，被删文章消失
- 误点删除有二次确认保护

---

## 开发顺序建议

```
阶段一（后端鉴权）→ 阶段二（上传接口）→ 阶段四（前端路由）
→ 阶段五（上传 UI）→ 阶段三（列表/删除/下载接口）→ 阶段六（列表 UI）
```

后端先行，每个阶段完成后用 curl / Postman 验收接口，再开始对应前端阶段。
